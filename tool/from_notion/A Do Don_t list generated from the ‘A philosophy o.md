# A Do/Don't list generated from the ‘A philosophy of software design’

Published On: July 19, 2025
Author: dilawar
Status: Draft

This post is not a typical review of the book. You can find some excellent review of this book [here](https://blog.pragmaticengineer.com/a-philosophy-of-software-design-review/). Here I am going to split the recommendation from the book in three categories `L1`, `L2` and `L3`. Every entry level programmer should think about `L1`. A mid-level programmer will benefit by thinking about `L2` and perhaps `L3` as well. If you are designing a large system, you must think about `L3`.

In my opinion, you are `L1` if you are constantly told things you should not be doing during code review.
